# IAML — second language (Mongolian)

The site exists in **English** (`en`, the source and the fallback) and **Mongolian** (`mn`, Khalkha, Cyrillic script — the
same script as the association's seal "ОЛОН УЛСЫН МОНГОЛ ХЭЛ СУДЛАЛЫН НИЙГЭМЛЭГ / ОУМХСН"). The admin panel stays English.
Everything below is the contract between the front-end (`assets/js`), the backend (`backend/`) and the admin panel.

> **Translations are drafts written by an AI assistant and must be reviewed by a native Mongolian speaker (ideally a linguist)
> before the Mongolian version is announced.** Terminology is fixed in the glossary at the end so a reviewer can change a
> term in one place.

## 1. How the language is chosen

* One set of URLs. The language is picked at run time: `?lang=mn` (remembered in `localStorage["iaml-lang"]`) → remembered
  choice → browser language `mn*` → English. `<html lang="mn">` is set before first paint.
* Header switcher **English | Монгол** (full names, at the left of the header next to the seal; also in the burger menu when the bar has no room): stores the choice, removes `?lang=` from the address and reloads,
  so that dynamic content is fetched again in the new language.
* The static GitHub Pages draft works the same way — the dictionary is a static file, no backend is needed for the UI text.

## 2. Front-end engine (`assets/js/i18n.js`, dictionary `assets/js/i18n-mn.js`)

English is the key. The dictionary maps **English string → Mongolian string**. A missing entry leaves the English text.

Every page loads, in this order:
```html
<script src="assets/js/i18n.js?v=…"></script>             <!-- in <head>, blocking, tiny -->
…
<script defer src="assets/js/i18n-mn.js?v=…"></script>    <!-- FIRST of the deferred scripts -->
<script defer src="assets/js/api.js?v=…"></script> …
```

| Markup | Meaning |
|---|---|
| `<h2 data-i18n>About Us</h2>` | text content of a **leaf** element is the key (whitespace is normalised) |
| `<p data-i18n="html">Write to <a href="…">us</a>.</p>` | the normalised `innerHTML` is the key and is replaced by the (trusted) dictionary value |
| `<input data-i18n-attr="placeholder aria-label" placeholder="E-mail">` | the listed attributes are translated, their English value is the key |
| `<title data-i18n>` and `<meta … content="…" data-i18n-attr="content">` | page title / description / og tags |
| `IAML.t("Welcome back, {name}.", { name: first })` | strings built in JS; `{name}` placeholders are kept in the translation |

Rules: one sentence = one key (do not split sentences around inline markup, use `data-i18n="html"`); never build a sentence by
concatenating translated pieces; numbers and dates go through `IAML.fmt`; text created by JS **after** load that contains static
markup can be translated with `IAML.i18n.apply(node)`. API data is never translated by the engine (see §3).
`IAML.i18n.missing` lists every string that was requested without a translation (use it in the browser console to check a page).

Dates: the site keeps showing **UTC+3**. `IAML.fmt.chip/long` use Mongolian month labels when `IAML.i18n.lang === "mn"`
(`"{n}-р сар"`, long form `"{y} оны {m}-р сарын {d}"`); the numeric `2026-10-15 · 14:30 (UTC+3)` format is language neutral.

Fonts: DM Sans has no Cyrillic. Cormorant Garamond has Cyrillic (and Ө/Ү via `cyrillic-ext`); **Inter** is added to the Google
Fonts request and to the body font stack so that Mongolian body text is rendered consistently. Mongolian text is ~20–30 % longer than
English: check the header navigation, buttons, date chips and cards at 375 px.

## 3. API (see also `docs/API.md`)

**Public GET endpoints** accept `?lang=en|mn` (default `en`; anything else = `en`): `/api/menu`, `/api/pages/:slug`, `/api/news`,
`/api/events`, `/api/publications`, `/api/participants`, `/api/links`, `/api/contacts`. `assets/js/api.js` adds the parameter
automatically to every non-admin GET when the UI language is not English.

* Field names do not change; the values are localised.
* **News, events, publications, pages** carry `"lang": "mn" | "en"` = the language of the text actually delivered. With `?lang=mn`
  and no Mongolian text the English text is delivered with `"lang": "en"` (the UI shows a small "EN" badge so a reader knows the
  item is not translated). An item counts as translated when its Mongolian **title and main text** exist (events: the title).
* Menu, participants, links, contacts: silently localised with fallback to English per field.
* `GET /api/contacts` → `address` comes from the setting `contact.address_mn` when present.
* `User` (`/auth/*`, `/me`) has `"lang": "en" | "mn"` — the language of e-mails. `POST /auth/register` takes an optional `lang`
  (the front-end sends the current UI language), `PATCH /me` takes `lang`.
* **E-mails** (confirmation / reset / "account exists" / Mongolist digests) are sent in the user's `lang`; digests use the
  Mongolian title of an item when it exists. Contact-form notifications to administrators stay English.
  The one-click unsubscribe page speaks Mongolian when its link has `&lang=mn` (digest e-mails add it).

**Admin API** — every translatable resource gets optional `*_mn` fields (empty string / null = "not translated", same limits as the
English field). List/detail items also carry `has_mn` (boolean) for news, events, publications and pages.

| Resource | new fields |
|---|---|
| `news` | `title_mn`, `body_mn` |
| `events` | `title_mn`, `location_mn`, `summary_mn`, `body_mn` |
| `publications` | `title_mn`, `topic_mn`, `summary_mn` |
| `pages` | `title_mn`, `body_mn` |
| `menu` | `title_mn` |
| `positions` | `name_mn`, `singular_mn` |
| `participants` | `name_mn`, `org_mn` |
| `link-categories` | `title_mn`, `blurb_mn` |
| `links` | `title_mn`, `description_mn` |
| `contact-people` | `position_mn`, `name_mn` |
| settings | `contact.address_mn` |
| users (list) | `lang` |

Admin forms show these fields in a "Mongolian version (optional)" section under the English ones.

## 4. Checking completeness

`cd backend && npm run i18n:check` lists every `data-i18n` / `data-i18n-attr` / `IAML.t("…")` string used by the site that has no entry
in `assets/js/i18n-mn.js`, and entries that are no longer used. It runs as part of `npm test`.

## 6. Implementation notes (front-end)

* **Server messages.** API errors arrive in English. `IAML.tServer(message)` (assets/js/app.js) translates them: exact table of the
  messages the backend can send + a few regex rules for parameterised ones (`must be at most {n} characters`). Field errors are composed
  with the template `"{field} {message}"`. A new backend message needs a literal `t("…")` entry there and a dictionary line.
* **Untranslated content badge.** `IAML.langBadge(item)` shows a small "EN" badge when the UI is Mongolian and `item.lang === "en"`
  (news / events / publications cards and modals, custom pages).
* **Menu cache.** The menu answer is cached per language in `localStorage` (`iaml-menu`, `iaml-menu-mn`).
* **Switcher.** Full names "English | Монгол" as a segmented pill, one copy at the left of the header (`.nav__left`, after the seal); when the bar
  has no room it first hides the association name (tablets) and then moves to the first item of the burger menu (`body.nav-lang-menu`).
* **Not translated on purpose.** `<noscript>` texts (the engine needs JS), the fake sample content of the static draft (sample news, events,
  threads, roster), the honeypot field label and the SVG seal text.
* **Gotchas.** Every public JS file uses `t` as a local alias of `IAML.t` — do not name another variable `t`. `apply()` marks a node done even
  when no translation exists yet, so entries added to the dictionary later need `data-i18n-done` removed before a second `apply()`.
  `npm test` runs the completeness check, so a new `data-i18n` / `t("…")` string without a Mongolian entry fails CI.
